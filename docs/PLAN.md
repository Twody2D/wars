# Кубо-войнушка — план проекта (v2)

25.09.2026 · Twody

Что изменилось в v2: убраны CI/CD, Docker и VPS; всё собирается у тебя в редакторе Godot и вручную загружается в Яндекс Игры. Добавлены бюджет сборки меньше 10 МБ, работа через редактор, адаптация под ПК и телефон, бот-противник и чек-лист требований Яндекса по пунктам. Промпты для Claude Design лежат отдельно, в `docs/PROMPTS.md`.

## 1. Концепция

2D-битва на одной линии: слева база игрока, справа база бота. Игрок тратит еду на юнитов, бот воюет по сценарию уровня. Побеждает тот, кто разрушит чужую базу. Прогресс идёт по биомам, аудитория — дети 7–14 лет. Платформа — только Яндекс Игры, ПК и телефоны, **горизонтальная ориентация**.

**Про персонажей.** Юниты — классические типы мобов (зомби, скелет-лучник, паук, слизень, голем), но нарисованные в своём дизайне, а не копии мобов Майнкрафта. Копии не пройдут модерацию: пункт 3.6 запрещает копировать чужие игры, плюс действуют права Mojang/Microsoft.

**Про название.** Слова «война» или «war» в названии лучше не использовать: пункт 3.4.4 запрещает отсылки к войнам и конфликтам. Фэнтезийные «битвы» при этом допустимы. Название должно быть уникальным в каталоге (5.12).

### MVP

- Биомы 1–2, 6 юнитов, 2 босса, 20 уровней (больше 10 минут игры, как требует пункт 2.9).
- Еда в бою, монеты между боями, апгрейды юнитов и базы, одна способность базы.
- Yandex SDK: реклама за награду, межэкранная реклама, облачные сохранения, лидерборд, язык.
- Языки ru и en.
- После MVP: биомы 3–6 обновлениями, затем покупки скинов.

## 2. Движок и размер сборки меньше 10 МБ

Остаёмся на Godot 4: у него полноценный визуальный редактор (сцены, инспектор, редактор анимаций), а тебе это важно. Проблема одна: стандартный web-шаблон Godot 4 весит около 42 МБ, в zip — около 8,7 МБ, и это ещё без игры. Решение — собрать свой облегчённый шаблон один раз: без 3D и без лишних модулей он весит около 17 МБ, в zip — около 3,7 МБ ([замеры](https://popcar.bearblog.dev/how-to-minify-godots-build-size/)).

Альтернатива — Defold: сборки 2–3 МБ, есть готовый [YaGames SDK](https://github.com/indiesoftby/defold-yagames). Но в нём нет такого редактора анимаций, и придётся учить Lua. Для твоих целей Godot с облегчённым шаблоном подходит лучше.

### Бюджет архива

| Часть | Размер в zip | Как держим |
| --- | --- | --- |
| Движок (облегчённый шаблон) | ~3,7 МБ | Свой web-шаблон, раздел ниже |
| Графика | ≤ 2,5 МБ | SVG → текстуры маленького размера, атласы, WebP |
| Звук | ≤ 2,0 МБ | OGG, моно, 64–96 кбит/с; музыка — короткие зацикленные треки |
| Шрифт | ≤ 0,2 МБ | Один шрифт, только латиница и кириллица |
| Сцены, данные, SDK | ≤ 0,5 МБ | — |
| **Итого** | **≤ 9 МБ** | Проверяем размер zip перед каждой загрузкой |

### Облегчённый web-шаблон (один раз, на Windows)

1. Поставить Python 3, SCons (`pip install scons`) и Emscripten SDK той версии, которую требует документация твоей версии Godot.
2. Скачать исходники Godot того же тега, что и редактор (например, `4.x-stable`).
3. Собрать шаблон:

```bat
scons platform=web target=template_release ^
  optimize=size lto=full threads=no ^
  disable_3d=yes ^
  module_text_server_adv_enabled=no module_text_server_fb_enabled=yes ^
  build_profile=custom.build
```

4. `custom.build` — профиль неиспользуемых классов. В Godot 4.4+ его создаёт сам редактор: **Project → Tools → Engine Compilation Configuration Editor** находит, какие классы игра не использует.
5. `javascript_eval` не отключать: через него работает плагин Yandex SDK.
6. В пресете экспорта Web указать собранный шаблон в **Custom Template → Release**.

Если сборка на Windows не пойдёт, облегчённый шаблон можно один раз собрать на бесплатном раннере GitHub и просто скачать. Для этого не нужен ни VPS, ни постоянный CI.

### Настройки проекта для размера и скорости

- **Rendering → Renderer:** Compatibility (WebGL 2, лучше всего на слабых телефонах).
- **Export → Resources:** экспортировать только используемые ресурсы. В папках `art_source/` и `store/` лежит пустой файл `.gdignore`, поэтому исходники SVG и промо-арт не попадают в сборку.
- **Импорт SVG:** масштаб под игровой размер (юнит ~128 px в кадре). Фоны — Lossy WebP с качеством 0,8, остальное — Lossless.
- **Атласы:** `AtlasTexture`/`SpriteFrames` для эффектов, все иконки UI — в одном атласе.
- **Звук:** SFX в OGG моно, по 3–10 КБ; музыка — 2 трека по 60–90 с, зацикленные, ~0,6 МБ каждый.
- **Пул объектов** для юнитов, снарядов и эффектов: без `instantiate`/`queue_free` в бою, чтобы не было подтормаживаний.
- **Лимит на поле:** не больше 40 юнитов. Цель — 60 FPS на ПК и 30+ на слабом телефоне.

## 3. Работаем через редактор

Правило: **всё, что видно и настраивается, делается в редакторе Godot, а код — только логика**. Тогда баланс, уровни и анимации меняются без правки кода.

| Что | Где редактируешь | Формат |
| --- | --- | --- |
| Характеристики юнитов | Инспектор, файл `data/units/*.tres` | `UnitData` (Resource) |
| Уровни и сценарий бота | Инспектор, `data/levels/*.tres` | `LevelData` с массивом `WaveEntry` |
| Сборка персонажа из частей | Сцена `art/units/<id>/<id>_visual.tscn` | Sprite2D на каждую часть |
| Анимации walk/attack/die | Нижняя панель **Animation** | AnimationPlayer |
| Базы, фоны, параллакс | Сцена `battle.tscn` | Parallax2D, Sprite2D |
| Интерфейс | Сцены `ui/*.tscn` | Control-узлы, якоря, темы |
| Тексты | `localization/translations.csv` | ключ, ru, en |

Скрипты используют `@export` и `@tool`, поэтому изменения сразу видны в редакторе.

## 4. ПК и телефон

Одна сборка для обоих типов устройств. Базовое разрешение 1280×720, растягивание `canvas_items`, аспект `expand`: на широких экранах видно больше фона, но интерфейс не обрезается.

| Требование | ПК | Телефон |
| --- | --- | --- |
| Управление | Мышь + клавиши: `1`–`6` — юниты, `Пробел` — способность, `Esc` — пауза. Берём `physical_keycode`, чтобы не зависеть от раскладки (1.6.2.4) | Только тапы, одной рукой (1.6.1.5, 1.10.4): карточки юнитов внизу, кнопка способности справа |
| Поле | Растягивается до края области, длинная сторона не больше двух коротких (1.6.2.1, 1.6.2.2): при `expand` ограничиваем соотношение 2:1 | Полноэкранный режим в бою (1.6.1.1) |
| Ориентация | — | Горизонтальная. В портретной ориентации показываем экран «поверните устройство»; игра на паузе, прогресс не теряется (1.9) |
| Выделение и меню | Нет выделения и контекстного меню (1.6.2.7) | Долгий тап не выделяет текст и не открывает меню (1.6.1.8) |
| Размер элементов | Кнопки от 48 px | Зона нажатия от 96 px в базовом разрешении (1.8) |
| Звук | Пауза звука при потере фокуса вкладки (1.3) | То же при сворачивании браузера |

Выделение и контекстное меню отключаем в своём HTML-шаблоне экспорта (`Custom HTML Shell`):

```html
<style>
  html, body, canvas { margin:0; overflow:hidden; touch-action:none;
    user-select:none; -webkit-user-select:none; -webkit-touch-callout:none; }
</style>
<script>
  document.addEventListener('contextmenu', e => e.preventDefault());
</script>
```

Пауза при потере фокуса — в Godot через `NOTIFICATION_APPLICATION_FOCUS_OUT`, а также через события SDK `game_api_pause` и `game_api_resume` (1.19.4).

## 5. Архитектура

```
res://
├── addons/              # плагин Yandex SDK (версия и SHA — в ADDONS.md)
├── art/                 # импортируемая графика (SVG из Claude Design)
├── art_source/          # исходники и *_parts — с .gdignore, не в сборке
├── store/               # иконка и обложка каталога — с .gdignore
├── audio/
├── data/
│   ├── units/*.tres     # UnitData
│   └── levels/*.tres    # LevelData + сценарий бота
├── localization/
├── scenes/              # boot, menu, map, battle, unit, base, ui/*
├── scripts/
│   ├── autoload/        # Events, GameState, SaveService, Platform, Audio
│   ├── battle/          # unit.gd, base.gd, economy.gd, bot.gd, pool.gd
│   ├── data/            # unit_data.gd, level_data.gd, wave_entry.gd, save_data.gd
│   └── platform/        # platform_yandex.gd, platform_mock.gd
├── web/                 # custom_shell.html
└── tests/
```

| Автозагрузка | Задача |
| --- | --- |
| `Events` | Глобальные сигналы — сцены не знают друг о друге |
| `GameState` | Монеты, пройденные уровни, апгрейды |
| `SaveService` | Сохранение, версия схемы, проверка данных |
| `Platform` | Реклама, облако, лидерборд, язык, пауза. В редакторе — заглушка `platform_mock.gd` |
| `Audio` | Музыка и звуки, глушит всё при паузе и рекламе |

Юнит: `UnitData` (характеристики) + сцена-визуал (части и анимации) + машина состояний `Walk → Wait → Attack → Dead`. Логика боя не зависит от графики, поэтому бой можно гонять в тестах без отрисовки.

### Бот-противник

Бот — не «интерактивный ИИ» из запрета 1.23, а обычный сценарий уровня. Он настраивается в инспекторе:

```gdscript
# scripts/data/wave_entry.gd
class_name WaveEntry
extends Resource

@export var time_sec: float = 0.0          # когда выпустить
@export var unit: UnitData
@export_range(1, 20) var count: int = 1
@export var interval_sec: float = 0.8      # пауза между юнитами в пачке
```

```gdscript
# scripts/data/level_data.gd
class_name LevelData
extends Resource

@export var biome: StringName = &"meadow"
@export var bot_base_hp: int = 500
@export var bot_food_per_sec: float = 1.0  # бот тоже копит еду
@export var waves: Array[WaveEntry] = []   # жёсткий сценарий (имя script занято у Object)
@export var counter_pick: bool = false     # реакция на армию игрока
@export var reward_coins: int = 20
```

Бот делает две вещи: выпускает волны по расписанию `waves` и, если включён `counter_pick`, тратит накопленную еду на ответ. Например, игрок шлёт много ближников — бот отвечает лучниками. Сложность растёт через `bot_food_per_sec`, состав волн и HP базы, так что нарастающая сложность (2.8) настраивается без кода.

## 9. Безопасность

Сервера нет, всё работает в браузере игрока. Поэтому сборку считаем публичной, а сохранения и ответы SDK — недоверенными.

| Риск | Защита |
| --- | --- |
| Правка сохранения через DevTools | `SaveService` проверяет типы и диапазоны, отбрасывает лишние ключи, зажимает числа. Цель — чтобы чит не ломал игру |
| Фейковые рекорды | Предел правдоподобия очков за время и волну |
| Двойная награда за рекламу | Только по `onRewarded`, один раз на показ, кнопка блокируется до закрытия рекламы |
| Битое или старое сохранение | `schema_version` + миграции; при ошибке — предыдущая копия, а не сброс |
| Вызовы JavaScript | `JavaScriptBridge.eval` только с константными строками; ответы SDK проверяются |
| Покупки (после MVP) | Только через SDK: выдать → сохранить → `consumePurchase`; при старте обработать незавершённые (1.13) |
| Дети | Никаких персональных данных, чатов и внешних ссылок (8.4) |

## 12. Git-процесс

Conventional Commits, без `Co-Authored-By`. Типы: `feat`, `fix`, `refactor`, `perf`, `test`, `build`, `docs`, `chore`. Области: `battle`, `bot`, `data`, `save`, `platform`, `meta`, `ui`, `art`, `audio`, `i18n`, `balance`.

Хук `.githooks/commit-msg` (подключить один раз: `git config core.hooksPath .githooks`, работает в Git Bash):

```bash
#!/usr/bin/env bash
msg_file="$1"
first_line=$(head -n1 "$msg_file")
pattern='^(feat|fix|refactor|perf|test|build|docs|chore)(\([a-z0-9-]+\))?!?: .{1,72}$'

if ! [[ "$first_line" =~ $pattern ]]; then
  echo "Коммит не по Conventional Commits: $first_line" >&2
  exit 1
fi
if grep -qi '^co-authored-by:' "$msg_file"; then
  echo "Строки Co-Authored-By не добавляем" >&2
  exit 1
fi
```
